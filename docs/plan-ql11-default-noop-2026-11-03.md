# QL11 默认增量无新增：正确noop与输入失败分离

基线 `bce9613b19ecbd806b96f52e0be5efe09464d11c`，#115对齐修复保留。
缺陷是默认增量将start设为旧末尾+1秒，来源已追平时合法staging为空，但编排器直接报错。

本片仅修复默认自动start的空增量判断；显式start、rebuild、skip-stage空结果不放行。

- 现有staging扫描可选带回来源行数、可用历史行数、源日期范围、坏时间数、窗口内原始行数；
  默认公开返回值仍为路径列表，无重复读湖，无新下载，无单位/价格/去重/字段写法修改。
- 自动增量开始前核验配置的根目录、来源文件和显式名单匹配；缺源必须在清理旧staging前失败。
  默认枚举时已有空占位分区可沿用跳过，但整个请求没有可用来源不能noop。
- 空增量仅在至少一个可用历史来源、窗口内确无任何原始行、无坏时间时进入noop。
  显式请求的每个证券都须有可用来源；仅有新坏close导致过滤为空的情况拒绝。
- noop前验证旧分钟轴有序唯一，以及相关既有provider的close bin结构和全轴边界；
  新增名单证券没有bin时失败，不用noop掩盖未导入的证券。实际provider不变，仍写原schema回执。
- 真实湖验收使用#115同一已建测试provider的全新副本；不传start/end走默认自动增量，
  核对noop和完整provider文件指纹不变。额外跑坏根/未知名单/空源/坏数据拒绝，不能只验成功格。
- 默认日频/provider未切换；不接MyQuant-infra搬迁，不改交易或源湖。P12保持整包开放。

验证包括真实CLI布线的离线负向矩阵、既有staging/追加回归与宿主原CLI。CI绿＋固定实现复核通过即合。

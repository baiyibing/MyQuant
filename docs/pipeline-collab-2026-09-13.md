# 协作流水线：任务书 → 实现 → CI → 宿主实跑 → 预锁判读 → 回写

- 日期：2026-09-13（两天实战固化；前身 = 中期计划 §0 硬约束 + 路线图回写惯例）
- 定位：**跨 agent/跨人的软件交付流水线 SSOT**。MyQuant 首用并全量验证（PR #7~#28），可平移到任何有 CI 的仓
- 配套：提示词 `my_docs/提示词-协作流水线.md`（发给实施 agent）；脚手架 `my_scripts/task_scaffold.py`

## 1. 六步流水线

| # | 步骤 | 谁 | 产出 | 门 |
|---|---|---|---|---|
| ① | **任务书** | 任务书作者（人/主持 agent） | `docs/plan-<slug>-<date>.md`：定位钉死 + 切片表（片/内容/验收）+ **判读预锁** + 明确不做 | 判读规则必须在结果产生**之前**写死 |
| ② | **实现** | Codex/Cursor/人 | `feat/`或`docs/` 分支，逐片小提交 | 只做任务书范围；发现任务书缺口→上报，不擅改 |
| ③ | **CI 绿** | GitHub Actions | checks 全绿（windows + py3.12 + qlib 钉版 + 全量 pytest） | **本地全量测试先过再 push**；CI 是第二道门不是第一道 |
| ④ | **宿主实跑** | 宿主（有数据/有机器的 agent 或人） | 真数据产物 + 验收记录 | 涉 18 分钟 handler 的验证**合批**；一次性脚本也要 main guard；产物三验（天数/字节/manifest） |
| ⑤ | **预锁判读** | 宿主 | 结论，严格按任务书第①步的预锁规则 | 单窗不算数；负结果/不可比/不改变名单都是**合法终点** |
| ⑥ | **回写** | 任一会话 | 路线图 §0 一行（数字 + 结论 + PR 号） | 只记已合入或本机验收过的；写完 PR + CI 绿合入 |

## 2. 预锁判读（流水线的灵魂）

**为什么**：单窗会骗人——两个实证：sweep 三月冠军 `topk5_ndrop2` 出窗垫底；特征 `turnover_resist` 三月 IC +0.138 出窗 -0.069 符号翻转。事后挑窗口/挑方法 = 自欺。

**怎么做**：任务书里写下（跑之前）——
1. 采纳条件（如「两窗同向」）
2. 合法终点清单（不可比 / 不改变名单 / 负结果——都算交付）
3. 禁止的说法（如「模型优于手工」「该改 topk」）
4. 预期管理（如「先量集中度再谈效果」）

**红线**：NAV 不当冠军；PortAna/单窗净值不判优；改线上默认参数需更高证据门槛（如第三窗）。

## 3. 角色与边界

| 角色 | 职责 | 不做 |
|---|---|---|
| 任务书作者 | 定位/切片/验收/预锁 | 不替实现者写代码 |
| 实现者（Codex/Cursor） | 分支/实现/全量测试/push/开 PR | 不合自己的 PR；不做任务书外的事 |
| CI | 客观门禁 | —（机器） |
| 宿主 | 真数据实跑/验收/判读 | 不越任务书预锁 |
| 回写者 | SSOT 一行级回写 | 不写长文进路线图 |

多会话并行守则：**动 git 前 `status` 对账**；不切别人正在用的分支；中途不切分支（manifest 取启动 commit 的教训）；进程失控按命令行定位进程树定点清理，勿盲杀。

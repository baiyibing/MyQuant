# QL11 分钟追加日历对齐与本机验收

冻结基线 `8f65e08685d47f3ed736409336726654a21723ae`。P12/QL11 既有工具只有离线回执；
本片用真实湖数据在全新隔离 provider 验证 rebuild → incremental → noop，并与独立 rebuild 读回比较。

已复现缺陷：旧日历09:30/09:31，个股仅09:30有值；新增日历09:32/09:33，个股仅09:33有值。
旧代码将11元直接接在10元后，实际读为09:31的价格，正确结果应在09:33，中间两格NaN。
旧回执仅检查probe条数未减少，不能识别这个错位。最小反例和baseline输出将随证据归档。

本片修改范围为 `refresh_mydata_1min.py` 的1min增量分支及对应测试，不改通用dump_bin、
日频、源行情、VWAP单位、策略或任何MyQuant-infra搬迁代码。

1. 追加按完整provider日历定位。校验磁盘旧日历与full_cal前缀、新后缀一致、轴严格有序无重复。
   每个旧bin校验4字节对齐、有限非负整数header、末尾未超过旧日历；后缀价格按全轴下标补NaN，
   旧字节前缀保持不变。新字段header也使用全轴位置。缺口不补价格。
2. 新日历沿用dump_all的已命名高频锚点并集，不只读取第一只票；仍不全市场收集Timestamp。
   新证券必须有full-stage，缺失明确失败；复用已解析lake_root。instruments边界保留实际观测时间。
3. 单文件临时写后replace；所有features成功后才发布instruments/calendar。
   不承诺整个provider跨文件事务。IO中断会非零、无成功回执；半成品不可消费，应从备份或rebuild恢复。
4. 测试覆盖旧尾缺口、新前缺口、非零header、新字段/新证券、非法旧bin/日历和锚点并集；
   与全轴rebuild结果比较，不能只按长度判通过。将真实增量测试接入现有装有qlib的CI选择。
5. 本机使用原有编排器CLI、真实股票/指数分钟湖、明确固定窗口和名单，输出至新的任务目录。
   逐字段bin读回并独立对照湖/staging的float32值，比较增量与重建，检查既有bin前缀、源hash和默认
   日频/provider/pred路径状态。默认provider当前不存在，如实记录缺失，不冒称保护了实际线上数据。

普通默认参数的“无新分钟→empty staging报错”另列尾项；本片noop使用显式原窗口重复执行，
要求实际原编排器返回noop回执。不以本片声明全市场provider刷新或P12整包关闭。
实现、宿主证据分别复核；CI绿＋复核通过按用户授权合入。

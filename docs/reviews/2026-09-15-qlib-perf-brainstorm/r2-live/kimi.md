## 卡 1 · 换手结构分解：强制出局 / 排序轮换 / 新进

- **标题**：名单日变化归因表（不碰 n_drop / hold 默认）
- **本仓锚点**：
  - `my_scripts/custom_train_backtest.py:350:380` 中 `TopkDropoutStrategy` 仍用 `topk=10`、`n_drop=3`、`hold_thresh=1`，`exchange_kwargs` 把 open/close/min_cost 写死；
  - `my_scripts/sweep_live_adapter.py:180:210` 的 `_simulate_list` 只产出日收益与 IC/IR，**不记录当日名单为什么变**；
  - PR #39 证据：topk50+四开关 收益 +8.4pp，但换手仍 **31.1×**——没人知道这 31 倍里是过滤踢得多，还是排序自己翻得多。
- **提案**（名单级 / 复验级）：在同 pred、同 topk/n_drop/hold 的前提下，对每日导出的 pool 做一份**变化归因**：
  1. **强制出局**：前日持仓因 ST/CYQ/资格/MA20 四开关任一被过滤掉；
  2. **排序轮换**：仍在候选池、但被 n_drop 机制淘汰；
  3. **新进补足**：模型新推入的票；
  4. **被动留存**：什么都没发生，只是多拿了一天。
  然后按这 4 类分别累计**零成本收益贡献**与**现实档成本消耗**。
- **收益**：把 PR #35 / #39 里「现实档 −1.5% / +9.1%」这格数字拆开，明确回答：**改哪一格能救现实档**——是四开关太凶（减过滤），还是 n_drop 太激进（加 hold / 减 ndrop），还是模型每天都在炒新票（信号层问题）。
- **成本与风险**：
  - 改动面 = 复验脚本读两帧 pool CSV 做 diff，**不训练、不导出、不改默认参数**；
  - 如果由此提案再动 n_drop / hold / 过滤子集 → **触发第三窗纪律**；
  - 需要前一天的完整候选池（而不仅是 TopK），当前 `export_daily_pool.py:190:240` 只写 TopK，候选池得从 pred 全量复算，成本可控。
- **冻结检查**：不碰硬纪律 1（不用 PortAna NAV 判优）；强化纪律 3（三成本档分开报）。
- **对抗预填**：
  - 过滤「强制出局」的票可能恰恰是次日 losers，所以“强制出局占比高”不等于减过滤就能转正；
  - 排序轮换高可能说明 pred 区分度差，不是 n_drop 的锅——此时加 hold 只是把毒尾捂久一点。
- **建议裁决**：裁剪后采纳
- **重提条件**：—

## 卡 2 · 多窗预锁包：把「同号同排序」升级成 sign-rank + 等权超额双门

- **标题**：topk50 系 OOS 预锁包的稳健化门
- **本仓锚点**：
  - `docs/plan-oos-sweep-segments-2026-09-13.md:40:50` 已写判读纪律，但只要求“两窗同号同排序”，没有指定统计口径与失败准则；
  - `my_scripts/sweep_ranking.py:240:250` 的 `summarize_ic_ir` 只按单点 IC/IR 排序，容易被一日异常拉偏；
  - HOST 锁定证据：三月冠军 `topk5_ndrop2` 出窗垫底 → 单点 IR 不可信。
- **提案**（复验级 / 纪律级）：在 2025 验证窗 + 2026-04~08 OOS 包里，把 survives 准则从“两窗同号且同排序”升级为以下**三门同时过**：
  1. **等权超额 sign 门**：两窗 topk50 的「零成本超额 vs 等权」同号；
  2. **排序稳健门**：两窗内 topk50 vs topk20 vs topk10 的相对排名用 Wilcoxon signed-rank 或至少「三日滚动 median 排名」一致，避免单日 IR 跳变；
  3. **现实档 sign 门**：两窗现实档净年化至少一正一平（不深负），否则直接标记为“成本结构不可救”。
  并预写 **早期停测门**：若两窗日命中率序列的皮尔逊相关系数 < 0.15，直接判定“窗口依赖”，不再跑第三窗。
- **收益**：把 HOST 首选后续从口号变成可执行、可证伪的任务书；直接防止 M3-B 冠军出窗惨剧重演；对 PR #35 的 topk50 单窗转正保持“研究-only”标签直到三门过。
- **成本与风险**：
  - 仅文档/任务书级改动，本轮不跑；
  - 若三门过后再改线上默认 → 触发纪律 2（第三窗佐证）；
  - 2025 验证窗长度可能不足， Wilcoxon 功效低，故用「三日滚动 median 排名」兜底。
- **冻结检查**：主动落实纪律 2、3；不碰纪律 1。
- **对抗预填**：
  - 稳健统计门太宽会把噪声当“稳健”，太严会错过真信号；三日滚动仍依赖窗内样本独立性，A 股日收益自相关会让 p 值虚低；
  - 两窗都正可能是同一市场因子在 two periods 同时顺风，不代表模型有 α。
- **建议裁决**：采纳
- **重提条件**：—

## 卡 3 · 成本档生死线：把 realistic 转正拆成「费率上限 × 换手上限」

- **标题**：现实档可兑现的 break-even 换手预算表
- **本仓锚点**：
  - HOST §2.A：topk50/n5 零成本 +5.1%，现实档 −1.5%，Δ ≈ −6.6pp；
  - `my_scripts/custom_train_backtest.py:365:375` 的 `open_cost=0.0005 / close_cost=0.0015 / min_cost=5` 是 qlib_default；realistic 档另行约定；
  - 纪律 3：三成本档必须分开报，不许用零成本冒充可上线。
- **提案**（纪律级 / 复验级）：对 topk10/20/50 + 过滤开/关每个臂，固定当前 pred，计算：
  - `break_even_turnover = zero_cost_excess_annual / per_trade_cost_rate`
  - 其中 `per_trade_cost_rate` 取 realistic 档全口径（手续费+滑点+冲击，以固定bps 表达），再与**实际年化换手**比较。
  产出列：`(actual_turnover - break_even_turnover) / break_even_turnover`，命名为 **DistanceToPositive**。预锁：若 DistanceToPositive > +20%（即实际换手比转正所需换手还高 20% 以上），该臂直接标为 **execution-structure 问题**，禁止再用 n_drop/hold 去拧。
- **收益**：把 PR #35 现实档 −1.5% 这格解释成“需要砍掉多少换手才能转正”，而不是含糊的“成本高”；避免在 signal 层面烧钱去救一个本应由执行栈/费率解决的问题。
- **成本与风险**：
  - 纯表格，零训练；
  - 不触发第三窗（不改默认）；
  - 危险：per_trade_cost_rate 本身也是假设；若后续 realistic 参数调整，DistanceToPositive 会变，所以必须冻结 realistic 假设版本号。
- **冻结检查**：无；强化纪律 3。
- **对抗预填**：
  - 低换手不一定等于好执行——名单里若是小票，即使换手低也可能冲击大，固定 bps 会低估；
  - 把“execution-structure 问题”标签打死后，可能让团队过早放弃本可通过 n_drop 微调救回的臂。
- **建议裁决**：采纳
- **重提条件**：—

## 卡 4 · 名单稳定性门：用留存曲线代替 hold_thresh 网格

- **标题**：TopK 名单日留存率观测 + hold 改参刹车
- **本仓锚点**：
  - `my_scripts/export_daily_pool.py:190:240` 当前只输出当天 TopK，没记录与昨日重叠；
  - `my_scripts/sweep_ranking.py:30:40` 把 `hold_thresh` 列为网格维度，但 M3-B 单窗已显示冠军出窗翻车；
  - R1 卡 5 把 hold/n_drop 细网格登记远期；本卡是把远期门做实。
- **提案**（名单级 / 纪律级）：
  1. 对 topk50 + 四开关整体（及关过滤对照）计算 **日 Jaccard** 与 **k 日留存率曲线**（k=1,2,3,5）；
  2. 预锁刹车线：**若 1 日 Jaccard 已 ≥ 70%，默认禁止增加 hold_thresh**（名单已经够稳，再捂就是路径依赖伪装）；
  3. **若 k=3 留存率 < 40% 且卡 3 DistanceToPositive 显示高换手缺口**，才允许在两窗 survives 后重启 hold∈{1,2,3} × n_drop∈{3,5} 细网格；
  4. 与 R1 P0-3 宇宙仪表盘联动：若池规模 < topk 的天数高，Jaccard 高可能是“没得选”，不能单读为稳定性。
- **收益**：解释 PR #39「收益 +8.4pp 但换手不变」——过滤可能只是换了一批同样高换手的票；给 R1 P2-1 hold 网格一个可操作的放行条件，避免永远挂起或永远不做。
- **成本与风险**：
  - 纯观测，零训练；
  - 若据此升 hold / 降 n_drop → 触发第三窗纪律；
  - 阈值（70% / 40%）是预猜，需等 2025 + 2026 OOS 数据后再校准，本轮不锁定。
- **冻结检查**：不碰硬纪律；升级改参时触纪律 2。
- **对抗预填**：
  - 高 Jaccard 可能来自候选池缩小（ST/CYQ 过滤后没几只可选），不是模型稳定；
  - 低留存率可能说明模型在追逐热点，加 hold 会把热点过期票继续持有，反而放大毒尾。
- **建议裁决**：裁剪后采纳（先做观测与刹车文案；阈值两窗数据后校准；hold 网格仍远期）
- **重提条件**：卡 2 两窗 survives 后，且卡 3 DistanceToPositive 显示换手缺口，且 k=3 留存率 < 40%。

## 卡 5 · 失败准则二阶：区分「窗口依赖」与「成本结构不可救」

- **标题**：OOS 失败标签的两种死法
- **本仓锚点**：
  - R1 卡 3 的失败准则只列了“深负 / Δ 翻号 / 换手不降”；
  - HOST §2.C 显示 M3-B 冠军是**窗口依赖**；§2.A 显示 topk50 是**成本档压死**——两码事。
- **提案**（复验级 / 纪律级）：在卡 2 预锁包里增加两个互斥失败标签：
  - **标签 A · 窗口依赖**：零成本或超额在 2025 窗与 2026-04~08 窗符号不一致，或日命中率相关 < 0.15 → 直接否决该配置，不进入第三窗；
  - **标签 B · 成本结构不可救**：两窗零成本/超额同号且排序稳，但**两窗现实档均 ≤ 0** → 不否决模型信号，但禁止再用 n_drop/hold/topk 救它，必须走执行栈/费率/路径依赖（出 Qlib）。
  禁止把标签 B 读成“模型不行”，也禁止把标签 A 读成“成本问题”。
- **收益**：防止 R3 裁决时把两种失败混为一谈；让卡 3 的 DistanceToPositive 和卡 4 的留存率有的放矢。
- **成本与风险**：零代码；但要求复验脚本同时输出三种成本档，不能事后挑选好看的那一列报。
- **冻结检查**：无；强化纪律 1/3。
- **对抗预填**：
  - 现实档假设本身可能因窗而异（2025 与 2026 流动性不同），把“两窗现实档均负”判成成本结构问题可能冤枉模型；
  - 标签 A 的 0.15 相关系数阈值是拍脑袋，可能被优化到“刚好 0.16”。
- **建议裁决**：采纳
- **重提条件**：—

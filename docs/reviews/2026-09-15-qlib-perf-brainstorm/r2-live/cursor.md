## 卡 1 · 否决/纪律〔全新发现〕：禁止把 PR #35 与 PR #39 的结果拼进同一张归因矩阵——它们不是同一份 pred

- **标题**：`4410e4a3` ≠ `95e18c5a`——宽度效应（§2.A）与过滤效应（§2.B）不可线性相加，"两机 pred 等价"证据强度不足以支撑跨表推断
- **本仓锚点**：`gh pr view 35` body 明写"本 PR 用**同一个 pred**（recorder `4410e4a3`……不重训）只改名单宽度做对照实验"；`gh pr view 39` body 明写"**新机无 `4410e4a3` recorder**，按预案改用本机同配置 2026 窗 pred（**`95e18c5a`**，manifest `train_20260913T105221Z`）——无过滤基线复算与发起机逐位一致（topk10 -46.5% / topk50 +0.6%），**两机 pred 等价**"。也就是说：HOST §2.A 表（宽度扫描）与 §2.B 表（四开关过滤）分别来自两个不同训练 run 产出的两份 pred，"等价"结论的唯一证据是「关过滤基线」两个数字（topk10 净年化 / topk50 净年化）在**一位小数**上重合，并非逐日名单 diff、pred 相关系数或 pred 文件 md5 级核验。同一份 PR #39 body 还自曝"CYQ 合并后 topk50 关过滤明细净值与合并前重回测基线不一致（明细自洽但净值差 -406 万）"——这恰好证明"汇总年化数字重合"完全可能掩盖"逐日名单/明细不一致"，两者不是同一件事。
- **提案**（纪律级）：明确否决/冻结任何形式的"把 §2.A 与 §2.B 当同一 pred 直接拼表"的操作，包括但不限于：① 把宽度效应 (+2.1pp) 与过滤效应 (+8.4pp) 相加/相乘估算"宽度+过滤"联合收益；② 用 §2.A 的 topk10/20/50 序列去解释 §2.B 里 topk50 过滤后 IR 为何改善（因为底层 pred 权重、甚至训练数据快照都可能不同）；③ 任何"topk×filter 联合网格"任务书（如 R1 grok 卡1/卡2、kimi 卡1）若要**同时**变化 topk 和过滤开关，必须先确认自己实际用的是哪一个 recorder，并在表头显式标注 recorder id，不得默认沿用 HOST 摘要表格的隐含假设。
- **收益**：防止一个"看似同源、实则跨模型"的证据链被合并叙述成"同一份 pred 上的完整实验矩阵"，从而虚增 R3/R4 裁决时对"宽度×过滤"组合效应的信心；这是纯纪律修正，不改变任何已发表的单表数字，只约束**跨表推理**的合法性。
- **成本与风险**：零代码成本，只是一条引用/组合禁令；风险是可能被认为"过度苛刻"——如果两个 recorder 训练配置（数据窗口、超参、种子）确实完全一致，则差异只来自训练随机性，跨表推断的偏差可能很小，本卡有"用力过猛拖慢士气"的可能，需要一个"够用即可"的解禁标准（见重提条件）。
- **冻结检查**：强化硬纪律 3（判优口径要可信）；不新增碰撞点；不涉及 topk/n_drop 默认本身。
- **对抗预填**：反驳可能是"两次训练用的是完全相同的 config/window/seed，LightGBM 在同一环境下是确定性的，1 位小数重合已经是强证据"——但即便如此，"新机"与"发起机"的浮点环境、qlib 版本、数据落盘顺序仍可能有细微差异（本仓 `docs/qlib-data-state-2026-09-13.md` 已记录过"close/adjclose 为 float32 舍入级差异"的先例），舍入级差异经过 166 日复利年化后完全可能被放大或抵消到看似一致，不能反推逐日一致。
- **建议裁决**：否决（否决的是"默认可跨表拼接/相加"这一推理动作，不否决 PR #35/#39 各自单表内部的结论）
- **重提条件**：核实方 hyphen 先做一次**弱验证**——用 §2.B 的"关过滤"名单（recorder `95e18c5a`）与 §2.A 的 topk50 名单（recorder `4410e4a3`）做逐日 Jaccard 重叠率，若中位数 ≥95%，可降级为"高置信度等价，允许标注注记后拼表"；若明显低于此，则必须彻底分开报告两个 recorder 的结果，任何联合网格任务书都要在新 pred 上重扫，不得复用旧宽度表数字。

## 卡 2 · 登记远期/纪律〔全新发现〕：多窗预锁包里的"2025 验证窗"已被训练早停消费，不能与"2026-04~08"同权重计入"两窗同号"门槛

- **标题**：`valid` 窗不是纯外部窗——kimi 卡2 / HOST 首选后续里的"两窗"实际是"一个训练内验证窗 + 一个真 OOS 窗"
- **本仓锚点**：`gh pr view 32` body 明写全市场长窗实验配置为"**train 2020-2024 / valid 2025 / test 2026-01-01~2026-09-08**"；本仓 `my_scripts/custom_train_backtest.py:234-270` 显示训练任务用 `qlib.contrib.model.gbdt.LGBModel` + `DatasetH`，`segments` 三段（train/valid/test）直接传给 `dataset.prepare`，而 qlib 的 `LGBModel.fit()` 默认行为是用 `valid` 段做 `early_stopping_rounds`（早停/最佳迭代选择），即模型权重的"该在哪一轮停止训练"这一决策**直接读取了 2025 年的表现**。HOST §2.A 脚注"首选后续：topk50 系在 **2025 验证窗** + 2026-04~08 OOS 同 pred 复验"、以及本轮 `r2-live/kimi.md` 卡2（多窗预锁包）都把"2025 验证窗"和"2026-04~08 OOS"并列当作**两个独立**的复验窗口，用于满足 M3-B 纪律"两窗同号且同排序才 survives"。
- **提案**（纪律级 + 复验级）：明确把"2025 验证窗"标注为**弱证据窗**（模型选择已消费），与"2026-04~08"这种模型训练全程未见过的**强证据窗**区分开。具体裁剪动作：① 在多窗预锁包（kimi 卡2/卡3、HOST 首选后续）文档里加一行免责声明："2025 窗结果反映的是'早停已经拟合过的窗口上的排序质量'，用于**校准/复现性检查**（例如确认同一 pred 文件在不同期间的稳定性），不能单独作为'模型在未见数据上排序质量'的证据"；② 把"两窗同号同排序"门槛升级为"**至少两个真正独立窗**同号同排序"——若第三窗（本轮未提及的、真正训练全程未见过的窗口，例如 2026-09 以后新增数据）暂不可得，则退而求其次：允许"2025(弱) + 2026-04~08(强)"作为**过渡性双窗**，但必须在结论措辞里显式标注"仅一强窗独立验证，不满足完整两强窗纪律"，不得直接写"两窗 survives"。
- **收益**：防止 R3/R4 收敛时把"2025+2026-04~08 同号"的说服力算得比实际更高——直接影响 P0-1（kimi 多窗预锁包）任务书写死的"survives"判据强度，避免重演 M3-B"三月冠军出窗垫底"式的虚假信心（M3-B 当时用的也是训练期之外的窗口，本次至少有一窗混入了训练内验证段，风险方向相同但更隐蔽）。
- **成本与风险**：纯文档/measurement 标注，零训练成本；风险是可能被认为"吹毛求疵"——早停只影响"迭代轮数"这一个超参，不直接决定排序规则本身，2025 窗的"污染程度"远小于直接把 2025 数据喂进训练集，过度强调可能让团队误以为 2025 窗完全不能用。
- **冻结检查**：与硬纪律 2（改参需第三窗佐证）直接相关——如果两窗里有一窗证据力打折，则"改线上 topk50 默认"所需的证据门槛事实上还没被满足，本卡加强而非放松纪律 2。
- **对抗预填**：可能反驳"早停只是防止过拟合的工程手段，不是'看过 2025 的 label 去调 topk/n_drop'，二者风险量级完全不同，不该混为一谈"——这条反驳部分成立，所以本卡明确不主张"否决使用 2025 窗"，只主张"降级其证据权重、加注免责声明"，避免被反驳者用"过拟合论"整体推翻。
- **建议裁决**：登记远期（先按"过渡性双窗+显式标注"方式裁剪采纳到 kimi 卡2 的预锁包文档里；真正的"第三个强证据窗"排期远期，待新数据/新时间点自然产生）
- **重提条件**：若团队能找到一段**训练与早停都未见过**的第三个窗口（例如未来新采集的 2026-09 之后数据，或者对同一 pred 重新训练一版"early_stopping 关闭、固定轮数"的对照模型来单独验证 2025 窗排序质量不依赖早停选择），则可解除"弱证据"标注，正式升级为两强窗。
